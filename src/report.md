### 4.1 Утилита iptables
Создаем файл `sudo vim /etc/firewall.sh`, имитирующий фаерволл на обеих машинах.
По умолчанию в нем должно быть : <br>
`#!/bin/sh`<br> `# Удаление всех правил в таблице «filter» (по-умолчанию).`<br> `iptables -F` <br> `iptables -X`<br>
Также в файл нужно добавить : <br>
1) стратегию, когда в начале пишется запрещающее правило, 
а в конце пишется разрешающее правило.
2) стратегию, когда в начале пишется разрешающее правило, а в конце пишется запрещающее правило.
3) открыть на машинах доступ для порта 22 (ssh) и порта 80 (http).
4) запретить echo reply (машина не должна «пинговаться», т.е. должна быть блокировка на OUTPUT).

![Файл на второй машине](screens/4.1a.ws2.png)<div align="right">*Файл на второй машине*</div><br>
Разница между стратегиями заключается в том, что в первом файле на ws1 применена стратегия, 
где в начале указываются запрещающие правила (DROP) для вывода (OUTPUT) данных, а затем разрешающие правила (ACCEPT) 
для ввода (INPUT) данных. Это означает, что машина ws1 блокирует исходящие (ответные) ICMP-сообщения, что делает ее 
непингуемой (не реагирует на пинги). Во втором файле на ws2 применена стратегия, где в начале указываются разрешающие 
правила (ACCEPT) для ввода (INPUT) данных, а затем запрещающие правила (DROP) для вывода (OUTPUT) данных. Это означает, 
что машина ws2 разрешает входящие ICMP-сообщения (пинги), но блокирует исходящие ICMP-сообщения (ответы на пинги).

### 5.5. Построение списка маршрутизаторов
Сначала нужно установить **traceroute** с помощью команды `sudo apt install traceroute`.<br>
Запускаем на r1 команду дампа `tcpdump -tnv -i enp0s8`.<br>
>-n - не конвертировать адреса в имена; > -t - не выводить время при выводе каждой строкчи дампа; > -v - при синтаксическом анализе и выводить более подробную информацию.
> Например, печатаются время создания, общая длина и параметры IP-пакета. 
> Также включает дополнительные проверки целостности пакетов, такие как проверка контрольной суммы заголовка IP и ICMP.

При помощи утилиты traceroute построили список маршрутизаторов на пути от ws11 до ws21.
![ws11](screens/5.5.ws11.png)<div align="right">*ws11*</div><br>
![r1](screens/5.5.r1.png)<div align="right">*r1*</div><br>
>Каждый пакет, отправленный через сеть, проходит через ряд промежуточных узлов, пока не достигнет своего конечного пункта назначения. 
> У каждого пакета есть предопределенное количество шагов, которое он может сделать по пути, прежде чем будет отброшен. 
> Это количество шагов записывается в заголовке пакета и называется TTL (Time to Live). Каждый маршрутизатор, через который проходит пакет, уменьшает значение TTL на один. 
> Когда TTL достигает нуля, пакет уничтожается, и отправителю отправляется сообщение об ошибке.
> Команда traceroute в Linux использует UDP-пакеты для отслеживания маршрута до целевого узла. Она начинает с отправки пакета с TTL, равным 1, 
> и записывает адрес первого откликнувшегося узла. Затем она отправляет пакеты с увеличенным TTL и продолжает этот процесс до тех пор, пока не достигнет целевого узла. 
> Для каждого TTL отправляются несколько пакетов, и измеряется время, за которое они достигают каждого промежуточного узла. Когда traceroute получает сообщение об ошибке о недоступности порта от 
> целевого узла, процесс трассировки завершается.
